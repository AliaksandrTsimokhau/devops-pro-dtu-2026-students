# Подключение к лабораторному стенду

У каждого студента своя лабораторная VM и свой kind-кластер на ней. Вход идёт по SSH-ключу через bastion-сервер: с ноутбука достаточно одной команды.

## Что нужно от вас

Передайте преподавателю:

1. **Публичный SSH-ключ.** Если ключа нет, создайте:

   ```bash
   ssh-keygen -t ed25519 -C "<ваш-email>"
   cat ~/.ssh/id_ed25519.pub
   ```

   Отправьте строку, которую выведет `cat`. Файл `id_ed25519` (без `.pub`) — приватный ключ, его никому не передавайте.

2. **Ваш внешний IP-адрес**, с которого вы будете подключаться:

   ```bash
   curl -s ifconfig.me
   ```

   Доступ открыт только с адресов, переданных преподавателю. Если вы сменили сеть (дом, университет, мобильный интернет), сообщите новый IP.

## Что вы получите от преподавателя

- `<имя>`: ваше имя пользователя.
- `<адрес_bastion>`: адрес bastion-сервера.
- `<адрес_вашей_VM>`: приватный адрес вашей VM.

## Подключение

Подставьте свои значения:

```bash
ssh -J <имя>@<адрес_bastion> <имя>@<адрес_вашей_VM>
```

Чтобы не вводить длинную команду, добавьте в `~/.ssh/config`:

```text
Host lab
  HostName <адрес_вашей_VM>
  User <имя>
  ProxyJump <имя>@<адрес_bastion>
  StrictHostKeyChecking accept-new
```

`StrictHostKeyChecking accept-new` сам запоминает ключ нового сервера без вопроса `yes/no`. Он не заменяет ключ, который изменился: если преподаватель пересоздал VM (например, после выходных), SSH остановится с ошибкой `REMOTE HOST IDENTIFICATION HAS CHANGED`. Решение ниже, в разделе «Если не подключается».

Если ключ лежит не в `~/.ssh/id_ed25519` (например, вы создали отдельный `~/.ssh/lab_key`), укажите его в отдельном блоке для обоих серверов. Флаг `-i` и `IdentityFile` внутри `Host lab` на промежуточный сервер (bastion) не действуют:

```text
Host <адрес_bastion> lab
  IdentityFile ~/.ssh/lab_key
  IdentitiesOnly yes
```

Дальше достаточно команды:

```bash
ssh lab
```

На bastion у вашего аккаунта оболочки нет: он нужен только как промежуточный узел для `ssh -J`. Работать нужно на своей VM.

## Если не подключается

| Симптом | Что проверить |
|---------|---------------|
| `Connection timed out` | Ваш текущий IP (`curl -s ifconfig.me`) совпадает с тем, что вы передали преподавателю. |
| `Permission denied (publickey)` | Вы используете тот ключ, чей `.pub` отправили. Укажите его явно: `ssh -i ~/.ssh/id_ed25519 lab`. |
| Вопрос `Are you sure you want to continue connecting` | Ответьте `yes`: так ключи серверов запоминаются при первом входе. |
| `REMOTE HOST IDENTIFICATION HAS CHANGED` | VM или bastion пересоздали, и у сервера новый ключ. Удалите старую запись и подключитесь снова: `ssh-keygen -R <адрес_bastion>` и `ssh-keygen -R <адрес_вашей_VM>`. Если вы не знаете, что сервер пересоздавали, сначала уточните у преподавателя. |

Для диагностики добавьте `-v`: `ssh -v lab`, и пришлите вывод преподавателю.

## Работа с кластером

1. На VM создайте кластер по лабе [lab-01-install-cluster](./k8s-advanced/lab-01-install-cluster.md).
2. Работайте с `kubectl` прямо на VM: дополнительно ничего настраивать не нужно.
3. После перерыва VM включаются заново, контейнеры kind запускаются сами. Проверьте:

   ```bash
   kubectl get nodes
   ```

   Все узлы должны быть в статусе `Ready`. Если нет, подождите минуту и повторите.

## Веб-интерфейсы на вашем ноутбуке

Чтобы открыть Grafana или своё приложение в браузере, пробросьте порт через SSH.

1. На VM запустите проброс из кластера (порты замените на нужные):

   ```bash
   kubectl port-forward svc/<сервис> 3000:80
   ```

2. На ноутбуке, во втором терминале:

   ```bash
   ssh -L 3000:localhost:3000 lab
   ```

3. Откройте в браузере `http://localhost:3000`.

## Доступ к API кластера с ноутбука (необязательно)

kind выбирает порт API случайно. Если нужен `kubectl` с ноутбука:

1. Создайте кластер с фиксированным портом: `networking.apiServerPort: 6443` в конфиге kind.
2. Скопируйте `~/.kube/config` с VM на ноутбук.
3. Пробросьте порт: `ssh -L 6443:127.0.0.1:6443 lab`.

Для курса достаточно работы на самой VM.
